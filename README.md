# VeloMarket — доска объявлений велосипедов и запчастей (только оригинал)

Сайт объявлений в стиле Kolesa.kz, только для вело-темы: велосипеды, запчасти, аксессуары.
Вход через Telegram, ручная модерация каждого объявления, фото серийного номера рамы, значок «Проверено», реклама в баннерах.

- **Сайт** (статический HTML/CSS/JS, без фреймворков) лежит в `site/` и публикуется на GitHub Pages:
  https://avtomaster24bot-lab.github.io/velomarket/
- **Бэкенд**: Supabase (база Postgres + Storage для фото + Edge Function для входа через Telegram).
- Пока в `site/js/config.js` нет ключей, сайт работает в **ДЕМО-режиме**: ненастоящие объявления с иллюстрациями, вход «демо-пользователь / демо-админ».

Название меняется в одном месте: `SITE_NAME` в `site/js/config.js`.

## Как устроен вход через Telegram

1. На `login.html` стоит официальный **Telegram Login Widget**. После нажатия Telegram отдаёт сайту `id, first_name, username, photo_url, auth_date, hash`.
2. Сайт отправляет эти данные в Edge Function **`telegram-auth`**.
3. Функция проверяет подпись: `HMAC-SHA256(data_check_string, SHA256(TELEGRAM_BOT_TOKEN))` и что `auth_date` не старше 24 часов. Подделать вход без токена бота невозможно.
4. Функция находит или создаёт пользователя в **Supabase Auth** (технический email `tg<id>@telegram.velomarket.app`, письма никуда не отправляются), создаёт одноразовый токен входа (`admin.generateLink`) и сразу обменивает его на **настоящую сессию Supabase** (`verifyOtp`).
5. Сайт получает `access_token` и `refresh_token` и вызывает `supabase.auth.setSession()`. Дальше всё работает через обычный Supabase с RLS.

Почему так, а не «свой JWT»: сессию выпускает сам Supabase, поэтому она работает и со старым JWT secret, и с новыми ключами подписи, обновляется сама (refresh token), а `auth.uid()` в политиках RLS работает как обычно.
Есть ограничение частоты: 10 попыток в минуту с одного IP (в памяти функции и в таблице `rate_limits`).

## Защита от подделок

- Каждое объявление создаётся как **черновик**. «Отправить на модерацию» (`submit_listing`) пропустит его, только если есть **≥3 общих фото + фото логотипа + серийный номер с фото**.
- Пока модератор не одобрит, объявление видят только владелец и админ.
- **Серийный номер и его фото** лежат отдельно (таблица `listing_verification` и приватный бакет `verification`) — их видят только владелец и админ.
- Бренд выбирается из справочника `known_brands` (202 реальных бренда велосипедов и запчастей с указанием страны). «Другой бренд» разрешён, но помечается **«усиленная проверка»**.
- Владелец не может сам одобрить объявление, поставить «Проверено» или «Топ», накрутить просмотры: это блокирует триггер в базе.
- Если изменить описание одобренного объявления, оно снова уходит на модерацию.
- В админке есть поиск дублей серийного номера, жалобы покупателей (`reports`) и кнопка «Снять объявление».

## Безопасность

- RLS включён на **всех** таблицах. Публично видны только одобренные объявления. Владелец видит свои, админ видит всё.
- **Минимум личных данных:** в `profiles` только `tg_id`, `username`, `first_name`, `is_admin`, `is_banned` и даты. Телефон, фото и фамилия не хранятся. Связь с продавцом только через Telegram, поэтому без username подать объявление нельзя (проверка в `submit_listing`). Данные лежат в Supabase, регион ap-southeast-1 (Сингапур).
- Профили чужих людей напрямую не читаются: имя и username продавца отдаёт `get_seller`.
- Пользователь не может изменить свой профиль через API (`is_admin` тоже); профиль обновляет только функция входа.
- Хранилище: фото до 5 МБ, только JPEG/PNG/WebP. Загружать можно только в свою папку `<user_id>/…`. Баннеры загружает только админ.
- В репозитории **нет секретов**. В `config.js` лежат только публичные URL и anon-ключ: они безопасны, если включён RLS. **Ключ `service_role` и токен бота хранятся только в Secrets Supabase.**

## Запуск: пошагово

### 1. Создать бота (2 минуты)
1. Откройте в Telegram **@BotFather** и отправьте `/newbot`. Придумайте имя, затем username, который заканчивается на `bot` (например `VeloMarketKzBot`).
2. BotFather пришлёт **токен** вида `123456789:AA…`. Это секрет: никому его не пересылайте, в чат тоже не вставляйте.
3. Там же отправьте `/setdomain`, выберите бота и укажите домен: `avtomaster24bot-lab.github.io`.

### 2. Создать проект Supabase
1. Зайдите на https://supabase.com, войдите через GitHub и нажмите **New project** (бесплатный план). Регион ближе к Казахстану: Frankfurt (eu-central-1).
2. Откройте **Project Settings → API** (или **Data API / API Keys**) и скопируйте:
   - **Project URL**, вида `https://abcdefgh.supabase.co`;
   - **anon / publishable key**: он публичный, его можно вставить на сайт;
   - **service_role / secret key**: никуда не копируйте. Edge Function получает его от Supabase сама.

### 3. Создать таблицы
> Если таблицы уже созданы старой версией, достаточно выполнить короткую миграцию `supabase/migrations/20261017000006_drop_phone_minimize.sql` (убирает телефон, фото и фамилию).

**SQL Editor → New query** → вставьте целиком `supabase/all_in_one.sql` → **Run**.
Также можно применить файлы из `supabase/migrations/` по очереди или выполнить `supabase db push`. Повторный запуск безопасен.

### 4. Развернуть функцию входа
**Вариант А, через сайт Supabase (без программ):**
1. **Edge Functions → Deploy a new function → Via Editor**. Назовите функцию ровно `telegram-auth`.
2. Сотрите пример кода в редакторе и вставьте целиком **один файл** `supabase/functions/telegram-auth/single-file.ts`
   (сырой текст: https://raw.githubusercontent.com/avtomaster24bot-lab/velomarket/main/supabase/functions/telegram-auth/single-file.ts). Нажмите Deploy.
3. В настройках функции **выключите «Verify JWT» (Enforce JWT verification)**: функцию вызывает ещё не вошедший человек.
4. **Edge Functions → Secrets → Add new secret**: имя `TELEGRAM_BOT_TOKEN`, значение — токен от BotFather. Вводите его **только здесь**.

**Вариант Б, через Supabase CLI:**
```bash
npx supabase login
npx supabase link --project-ref <ref-проекта>
npx supabase secrets set TELEGRAM_BOT_TOKEN=<токен-бота>
npx supabase functions deploy telegram-auth --no-verify-jwt
```
Необязательные секреты: `ALLOWED_ORIGINS` (по умолчанию `https://avtomaster24bot-lab.github.io`), `AUTH_MAX_AGE_SECONDS` (по умолчанию 86400).

### 5. Вставить ключи на сайт
Откройте `site/js/config.js` и заполните поля:
```js
SUPABASE_URL: 'https://abcdefgh.supabase.co',
SUPABASE_ANON_KEY: 'eyJ…или sb_publishable_…',
TELEGRAM_BOT_USERNAME: 'VeloMarketKzBot',   // без @
```
Сделайте commit и push в `main`. GitHub Actions сам опубликует сайт за 1–2 минуты. Демо-режим выключится автоматически.
Если ключи уже вставлены, а таблиц в базе ещё нет (или проект на паузе), сайт не ломается: он показывает баннер «Сайт настраивается» и демо-объявления, а примерно через минуту после создания таблиц сам переключается на настоящие данные.

### 6. Сделать себя админом
Войдите на сайт через Telegram один раз, затем в **SQL Editor** выполните:
```sql
update public.profiles set is_admin = true where username = 'GrifRift555';
```
(или `where tg_id = <ваш числовой id>`). После этого в шапке появится «Модерация» (`admin.html`).

### 7. (Рекомендуется) Закрыть регистрацию по email
**Authentication → Sign In / Providers → «Allow new users to sign up» → выкл.** Вход через Telegram продолжит работать: функция создаёт пользователей через admin API. После изменения проверьте вход ещё раз.

## Работа модератора
- **Очередь модерации**: старые объявления идут первыми. На карточке видны фото (с меткой «ЛОГОТИП»), фото серийника 🔒 и номер. Кнопки: «Одобрить», «Одобрить + ✓ Проверено», «Отклонить…» с готовыми причинами.
- **Все объявления**: снять или поставить «Проверено», **★ Продвигать (Топ)**. Топ-объявления показываются первыми и в блоке «Топ» на главной (бесплатно, включает админ).
- **Жалобы**: «Снять объявление» или «Отклонить жалобу».
- **Реклама**: баннеры в трёх местах: `home_top` (главная, 1200×240), `list_inline` (в списке, 1200×240), `listing_side` (сбоку на объявлении, 360×600). Картинку можно загрузить файлом или дать ссылкой. Есть даты показа и вкл/выкл.
- **Бренды**: добавить реальный бренд в справочник. **Курсы валют**: для сортировки цен между валютами.

## Тесты (что проверено)
- `tests/run_db_tests.sh`: применяет миграции на чистом PostgreSQL (вместо Supabase используется заглушка `tests/local_shim.sql`) и прогоняет 36 проверок RLS и триггеров.
- `tests/api_queries_test.mjs`: те же запросы, что делает сайт (supabase-js), идут через PostgREST к этой базе. 29 проверок: фильтры, сортировка, embed, rpc, избранное, жалобы, реклама, курсы.
- `deno test supabase/functions/telegram-auth/`: 11 юнит-тестов подписи Telegram (тестовый токен, независимая проверка через node:crypto).

## Важно знать
- Значок «Проверено» — решение модератора, а не гарантия. На сайте покупателям советуют сверять номер рамы при встрече.
- Бесплатный план Supabase: 500 МБ базы и 1 ГБ файлов. Это несколько тысяч объявлений, потому что фото сжимаются до ~200–400 КБ. Если проект неделю простаивает без запросов, Supabase ставит его на паузу; включается кнопкой в панели.
